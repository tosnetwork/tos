## 2026.12 Update

Tagged `v2026.12`. It follows `v2026.11-1` and is the release for the December public testnet. The Native Registry stays at its v1 release. Release assets are still Linux only, for x86-64 and arm64; the asset names and the build record are those of `v2026.11-1`, with one more build-record line (`gsl_package`) and three more files: `LICENSE`, `THIRD_PARTY_NOTICES.md` and `gsl-2.7.1-source.tar`.

1. Release build: the node binaries link GSL statically, so one release loads on Ubuntu 24.04 and on 26.04, whose GSL libraries have different sonames. The release publishes the corresponding source of the one GSL package version it links, `gsl-2.7.1-source.tar` (the Ubuntu source package of `libgsl-dev` `2.7.1+dfsg-6ubuntu2`), with the licence notices in `THIRD_PARTY_NOTICES.md`. The node build and the AppImage builds refuse any other `libgsl-dev` version. The AppImage tool archives still bundle the shared GSL library. `doc/tos-release-policy.md` records that the attestation identity was confirmed on `v2026.11-1`.
2. Networking: the largest overlay broadcast sent as a single signed broadcast rises from 768 to 4,096 bytes, so an ordinary external message signed with a post-quantum key (about 2.8 KB) is no longer split into FEC parts. Senders change; receivers already accepted simple broadcasts of any size. A version 1 overlay certificate with default flags now allows FEC only above 4,096 bytes, so nodes on either side of this change do not agree at that boundary: upgrade every node together. `doc/Validator.md` now requires `net.core.rmem_max = 33554432` on a node host, because the node's 16 MiB UDP receive buffer is otherwise capped at the kernel default and datagrams are dropped under load.
3. ConfigParam 84, the recognized settlement assets: a validator-governed list, keyed by token master account, of the bridged tokens that settlement contracts accept, with each token's status, decimals, code hashes, origin and per-actor liability cap. It is a critical parameter at genesis. `tosctl` decodes it, and builds or checks a value for a configuration vote.
4. Token bridge: the bridge token wallet supports reported transfers. A payer learns the outcome of each payout (delivered, refused by the receiving wallet, or bounced) as an authenticated report, and refusals stay recorded until cleared. The oracle multisigs may only send bounceable votes, without StateInit and with a bounded value, to an immutable allowlist of masterchain bridges fixed when the multisig is deployed, and no longer depend on a configuration parameter for that check. The source-chain bridge contract has per-token lock caps (total exposure, per lock, per fixed hour and per fixed day), changed only by an oracle vote. A token without caps cannot be locked, so every deployment must set caps for each token before its first lock. The bridge security notes now require a pinned, reviewed release of the exact build instead of external audits; the other pre-production conditions (oracle key ceremony, caps, monitoring, governance activation, canary and production signer) are unchanged.
5. Token-rail Service Actor (`tos-service-actor-token-v1`): a Service Actor whose calls are funded by a token transfer and whose payouts are reported transfers, admitting only tokens that ConfigParam 84 lists. `tosctl agent service-token` builds, checks and sends its calls and operator operations against the state of one masterchain block. A separate test-only build of each Service Actor (`-test` release manifests) shortens the minimum windows to 600 seconds for test networks; the release builds and their code hashes are unchanged.
6. `tosctl`:
   - `wallet send --valid-until <unix seconds>` sets the signed message's expiry, which must be between 10 and 3,600 seconds after the local clock. Without the option the expiry is the local clock plus 120 seconds, as before.
   - `wallet send --build-only` emits `tosctl.wallet-prepared-send.v2`, which always carries `valid_until`. The v1 output is removed: this is a breaking change for anything that reads it.
   - The stake max factor accepts 1.0 to 100.0, like the Fift tool. The default stays 3.0, ConfigParam 17 still caps the effective factor, and the value is now rounded to the nearest encoding instead of truncated.
   - `agent service send` prints the signed wallet message's seqno, expiry and hash before broadcasting it.
7. Fixes: when the ADNL external server refuses an asynchronously completed query, it now closes the connection in order, as the read path already did, instead of stopping at once with answers still queued. The kqueue and epoll pollers skip pending events of a descriptor that is unsubscribed during the same dispatch batch, which fixes an intermittent crash on macOS.
8. Platforms: macOS (Apple silicon and Intel), Windows (client tools), WebAssembly (contract tools) and Android (toslib as a JNI library) build from source and are built in CI. On Apple silicon a validator can use the ARMv8 SHA2 backend; an Intel Mac is not a validator host. Packaging scripts for macOS and Windows binaries exist, but this release publishes no macOS or Windows assets.
9. Tests and tooling: tests that waited fixed times now use virtual clocks or barriers; transport and product-build benchmarks; checks that the Service Actor release check runs in CI and that local-only refusal fixtures stay out of release inputs.
