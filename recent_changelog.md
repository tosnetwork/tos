## 2026.11 Update

The first published TOS release, tagged `v2026.11`. It carries everything in the 2026.10 update below, which was never published as a release, and the changes made since. It is also the first release whose node binaries are built with the production node recipe, so a node can be installed from the release instead of being built on each host.

1. Release binaries: validator-engine, validator-engine-console, lite-client, generate-random-id, tos-pq-consensus-key, dht-server, tos-rpc and tos-wallet-index are published as plain Linux binaries for x86-64 and arm64, built with jemalloc for a fixed CPU baseline (x86-64-v2, armv8-a), with a build record, `SHA256SUMS` and `release-provenance.json` binding every file to the build of the tagged commit. The AppImage archives remain the tool builds and are not the supported way to install a node. See `doc/tos-release-policy.md`.
2. Staking follows the upstream Elector design with ML-DSA-44 keys and signatures: a member is named by the account that sends its stake, an operator wallet or a nominator pool. The validator controller, the stake relay, operating authorizations, ConfigParam 47, `tos-pq-controller` and `tosctl controller` are removed. This replaces the controller-based election path described in the 2026.10 update.
3. Global version 16 opens every feature: the Falcon-512 signature check, the LMS fee-hash check and the c7 import statistics no longer wait for versions 17 to 19, and 16 is the highest version the binaries support.
4. Consensus: a validator records its own signing decisions and fences its start-up on every network, so a node restored from a copy or missing its consensus directory cannot sign a conflicting vote; each consensus key file is held under an exclusive lock. Simplex recovers skip timeouts and vote refusals across a finalization backlog, keeps a late candidate for a finalized slot, and bounds its candidate payload cache in bytes.
5. Networking and admission aligned with the upstream v2026.10 release: QUIC connection handling, Plumtree and overlay broadcasts, ADNL, and external-message admission with priority lanes, a configurable pool and ordered expiry. TOS-only limits on the external message pool, overlay broadcast receive and liteserver admission are removed in favour of the upstream ones.
6. Fees and genesis configuration: masterchain gas and forwarding prices at one twentieth of their earlier values; basechain external gas credit of 20,000; ML-DSA-44 verification priced like the Ed25519 check; SLH-DSA suite 3 verification at 4,500 gas; mainnet-scale basechain split parameters; a six-hour initial validator set with the first election inside it; blackhole, complaint and storage prices and the bootstrap amount set for the current genesis.
7. Token naming: "Jetton" is replaced by "Token" across contracts, tools, SDKs and documents. This is a breaking rename for anything that used the old names.
8. Wallets: the self-pay Quantum wallet, which pays its own fees and needs no fee vault, with a successor possession proof; wallet V4 and V5 commit the consumed seqno before executing the signed operation; wallet V5 refuses weak keys, unsendable modes and requests that would exceed the state-size limit; multisig refuses orders that cannot fit the basechain gas limit; `tosctl` requires an explicit wallet version. Activation of the Quantum wallet as the deployed default remains unapproved (`doc/wallet-quantum-release-status.md`).
9. Wallet services: wallet indexing and public JSON-RPC move out of the validator process into `tos-wallet-index` and `tos-rpc`, with verified index snapshots and resumable replay. A validator serves its JSON-RPC without the wallet index. JSON-RPC has one error contract with a strict envelope and parameter checks, and bounded post-quantum explorer evidence interfaces.
10. Shielded pool: the completed phase-2 ceremony is published with independent verification; `tosctl shield` covers client state, deposits, withdrawals, direct and relayed sends, also over Tor; the fixed withdrawal fee is 0.001 TOS; a native bridge serves mobile wallets. The pool remains **not approved for activation** until the acceptance gates of `artifacts/shielded-pool/PROFILE.md` section 19 pass.
11. Contracts and agent tooling: Treasury Vault V1 with mandatory guardian approval and delayed governance; Service Actor settlement that is caller-funded, protects the refund principal and accepts ML-DSA-44 attestors; Native Registry and Agent Account controllers on ML-DSA-44, with `tosctl` builders and signing; Action Authority messages; fixes for the smart-contract audit findings.
12. Bonded relayer (BR1) for relayed shielded withdrawals: bond actor, quote authentication with ML-DSA-44, bounded quote submission, durable relay core and a Tor onion transport. The provider is local-only by default; a public-testnet pilot needs an explicit build and runtime scope and is not a production approval.
13. Operators: verified node data recovery and node data sync, with validator recovery refused through generic snapshot imports; state import bounded against disk exhaustion; archive readers that write nothing into the node's tree; a report and metric for a node that stops applying the masterchain; pending election registrations kept valid through postponed starts; validator disk sizing guidance; `tosctl` packaged for NixOS.
14. Fixes: RaptorQ repair-symbol decoding and refusal of malformed peer symbols; refusal of a signature dictionary that is not in canonical form; a liteserver query cache bounded by the memory it owns; persistent-state and init-block refresh after genesis; absolute validator key expirations preserved by `tosctl`.
15. Verification: the Rust VM and transaction executor are aligned with the C++ implementation and compared on complete transaction roots; a replay corpus from real epochs runs on x86-64 and arm64; a conformance suite of nine harnesses with external vectors, chain and archive replay and fuzzing; local benchmark suites for post-quantum throughput and shard scaling.
16. Platforms: unchanged. Linux on x86-64 and arm64, built on Ubuntu 24.04; release binaries need glibc 2.39 or newer. Rust components are built with Rust 1.100.0.
