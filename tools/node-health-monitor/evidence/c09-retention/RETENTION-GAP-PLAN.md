## Minimal bounded implementation sequence proposed for approval

1. Freeze class policy **before source edits**: which new typed metric/event rows use 14d/7d and which clock is authoritative; whether raw process/witness rows can ever be pruned and how an old replay is answered; how many bytes are reserved for tombstones/summaries. Until approved, raw process/witness rows remain ineligible. A quota hit reports MonitoringUnavailable; it cannot mint freshness or erase an active episode.
2. Add a dry-run planner on **M's existing single evidence writer**. Page by indexed `(class, received_at_ms, store_seq)` with at most 256 candidates / 8 MiB / 5 seconds, deterministic signed-64 seq ordering, a persisted prune cursor, and an explicit candidate-versus-pin report. It must include current control `source_state` refs and any unresolved evidence refs; Q current retained origin seqs and exact current `(network,device,inode,watermark,anchor_seq,anchor_hash)`; quarantine and replay state. A missing/mismatched Q DB or clock/class field yields zero deletions. Do not scan all history then limit.
3. Before any delete, add a **shared M/Q retention fence**: Q import, cursor commit and grant creation hold a read lease; M purge holds an exclusive lease through its bounded Q pin snapshot and M transaction. Q/M restart or database replacement invalidates the lease. M's candidate delete transaction inserts sealed identity/hash/seq tombstones (or the separately approved monotonic source seal), verifies all pins and age in the same M snapshot, then deletes only eligible rows and advances its prune cursor atomically. A crash before commit changes nothing; after commit, replay finds the tombstone and cannot create a fresh row. Never prune the Q cursor anchor or currently retained Q parents. Keep Q's current evidence eviction behavior independent.
4. Add a separate Q terminal-ledger transaction: prune only revoked or expired same-/prior-boot grants, dependent attempts/bindings/packages, with an immutable bounded run-ID terminal receipt and preserved `attempt_seq` highwater. Active grants and their fixed W stay untouched. If the receipt budget is exhausted, refuse new grants explicitly. Do not delete Q origins just to free grant space.
5. Test failure atomicity at every page/receipt boundary; old same-hash and changed-hash replays after prune; sparse global M seq and non-process anchor; Q import/grant concurrent with purge; Q offline/replaced; active fixed-W late query; restart after M commit but before Q observation; quarantine; unresolved incident and pending outbox; quota/WAL/checkpoint pressure. The test that removes the tombstone or pin check must go red. Only then run disposable M/Q socket integration, backup/restore, and bounded cost profiles. No live rollout or 72-hour claim follows from synthetic tests.

Candidate source files after approval: `crates/health-services/src/durable.rs` (typed retention metadata/planner and M transaction), `diagnostic_ingest.rs` (event class/ingest timestamp and replay), `manager_query_source.rs` and `query_ledger.rs` (retention fence/pin snapshot and terminal ledger policy), `manager.rs` (bounded scheduling and MonitoringUnavailable), plus focused Rust/disposable M/Q tests and migration/rollback documentation. The fence protocol and raw-source TTL require owner approval before implementation; without those decisions, implement only a read-only dry-run report.
