## Minimal bounded implementation sequence proposed for approval

1. Freeze class policy **before source edits**: which new typed metric/event rows use 14d/7d and which clock is authoritative; whether raw process/witness rows can ever be pruned and how an old replay is answered; how many bytes are reserved for tombstones/summaries. Until approved, raw process/witness rows remain ineligible. A quota hit reports MonitoringUnavailable; it cannot mint freshness or erase an active episode.
2. Add a **read-only dry-run** inventory first. Page existing `observations.store_seq` with at most 64 rows / 1 MiB of body bytes plus fixed bounded scalar metadata / 5 seconds, report a page continuation sequence and provisional Q/control pin counts, and always output zero deletion candidates. Do **not** persist or advance a prune cursor from planning: a later activation must not skip unseen rows. The current schema lacks indexed class/clock columns, so unknown class/clock is unclassified, never age-eligible. A missing/mismatched Q DB, changed snapshot identity, or bound failure refuses the page. This inventory cannot prove a stable cross-database pin set and must not run a live deletion. A future typed `(class, received_at_ms, store_seq)` index needs separate migration/review before age-based pruning.
3. Before any delete, add the **shared M/Q retention fence** below, then let M's candidate delete transaction insert sealed identity/hash/seq tombstones (or the separately approved monotonic source seal), verify all pins and age in the same M snapshot, delete only eligible rows and advance its prune cursor atomically. A crash before commit changes nothing; after commit, replay finds the tombstone and cannot create a fresh row. Never prune the Q cursor anchor or currently retained Q parents. Keep Q's current evidence eviction behavior independent.
4. Add a separate Q terminal-ledger transaction: prune only revoked or expired same-/prior-boot grants, dependent attempts/bindings/packages, with an immutable bounded run-ID terminal receipt and preserved `attempt_seq` highwater. Active grants and their fixed W stay untouched. If the receipt budget is exhausted, refuse new grants explicitly. Do not delete Q origins just to free grant space.
5. Test failure atomicity at every page/receipt boundary; old same-hash and changed-hash replays after prune; sparse global M seq and non-process anchor; Q import/grant concurrent with purge; Q offline/replaced; active fixed-W late query; restart after M commit but before Q observation; quarantine; unresolved incident and pending outbox; quota/WAL/checkpoint pressure. The test that removes the tombstone or pin check must go red. Only then run disposable M/Q socket integration, backup/restore, and bounded cost profiles. No live rollout or 72-hour claim follows from synthetic tests.

Candidate source files after approval: `crates/health-services/src/durable.rs` (typed retention metadata/planner and M transaction), `diagnostic_ingest.rs` (event class/ingest timestamp and replay), `manager_query_source.rs` and `query_ledger.rs` (retention fence/pin snapshot and terminal ledger policy), `manager.rs` (bounded scheduling and MonitoringUnavailable), plus focused Rust/disposable M/Q tests and migration/rollback documentation. The fence protocol and raw-source TTL require owner approval before implementation; without those decisions, implement only a read-only dry-run report.

The permitted first subset is `scripts/plan-c09-retention-dry-run.py`. It opens private M/Q/control SQLite files with `mode=ro` and `query_only`, never issues DELETE/UPDATE, and reports at most 64 ordinary observation rows / 1 MiB with `store_seq` continuation, provisional pin counts (`pin_integrity=not_verified`) and **zero** deletion candidates. Process and historical witness TTL remain `undecided`; every other observation source is `unclassified` rather than assigned an event/metric TTL. No age eligibility is evaluated without approved class/clock metadata. The three read transactions are not one atomic cross-database snapshot, so the output cannot authorize a prune. It has only been run against disposable SQLite fixtures, not live M/Q/control. Its narrow tests hash all three fixture files before/after inspection, reject missing or older-than-W anchor/Q identity/over-bound origins, and assert unknown class never becomes eligible. No cursor or marker is persisted.

## Concrete fence contract for review, not enabled by existing Q/M

- **Owner and identity.** M's local supervision creates and fsyncs one non-replaceable regular lock file beside the M evidence DB before starting either coordinated process. Its approved UID/group grants only M and Q access; the path, device/inode, network and M/Q database identities are pinned in both configurations. Both open with `O_NOFOLLOW`, reject wrong mode/owner/link count or an inode change, and hold the opened FD for the process lifetime. An uncoordinated/older Q binary or missing lock file disables M deletion. This is a local-host proposal; separate production UIDs need an explicitly approved shared group, never a world-writable lock.
- **Acquisition order.** Always acquire the OS advisory lock **before** any Q ledger mutex/transaction or M evidence-writer transaction. Q takes a shared lock around every M read used for projection, the exact retained-parent check, every M-origin insertion (`insert_projection` and `insert_projection_page`), cursor commit, and final fixed-W grant commit; no grant is published after the shared lock is released unless its Q transaction committed. M retention takes an exclusive lock, verifies the running coordinated Q process and ledger identity, then obtains a bounded read-only Q snapshot of all retained origin seqs, active grants and exact global cursor anchor, then submits one bounded delete transaction to M's single evidence writer. An absent/replaced/offline Q gives zero deletions. Q's ordinary fixed-W handler needs no M read: all its retained parents were pinned at the fence. Direct diagnostic/collector M appends still serialize on M's writer and cannot be relabelled as Q evidence.
- **Deadlines and restart.** Use kernel FD-lifetime `flock` semantics, not an expiring time lease: a crash releases the lock only after the crashed process can no longer mutate its DB. Q shared acquisition gets at most 100 ms inside its existing 5-second operation deadline; on failure it refuses import/grant. M exclusive acquisition is nonblocking; a busy Q makes pruning skip this tick. A purge page is at most 64 rows / 1 MiB with a monotonic 1-second fence-hold budget and a 250-ms SQLite mutation budget; expiry aborts the transaction before releasing the FD and reports a skipped page. Reopen after crash revalidates lock inode, both DB identities, Q cursor anchor and tombstone/prune cursor; failure means zero deletion. If Q crashes before/after its cursor or grant commit, M's next locked Q snapshot sees the old/new durable state. If M crashes before/after its FULL commit, tombstone+delete+prune cursor are all absent/present together. No cross-database transaction is assumed.
- **Proof obligation.** Race tests must pause Q just before cursor/grant commit and M just before its delete, then show one side waits/skips and no retained parent/anchor disappears. Kill/restart each side at lock acquisition, Q commit, M transaction and lock release. Verify existing production Q cannot acquire the new fence, so no deletion is allowed while the current functional window runs. If the 1-second budget cannot be measured at maximum approved Q pin population, revise the design before enabling deletion; do not widen production query/cap deadlines to hide the cost.
