# Recover a sealed preparation after its reply is lost

Native preparation may commit immutable signed bytes before its IPC reply reaches Python. The durable Python job is then still reserved. A restarted recovery tick now asks the private native provider for recover_prepared, validates the original bytes/bindings, records those same bytes and enters the existing single-claim dispatch path. It never calls prepare again or re-signs.

The private recovery operation derives the exact canonical request ID, looks up its scoped native lease, reconstructs only the stored message/acceptance and calls the same complete historical validator as validate_prepared. This verifies the stored quote/signatures, release/worker/funding identity, slot/time/value/sequence and exact Shield body. It does not refresh the quote or require an old quote to remain current. No lease means no sealed native attempt; an unsigned/interrupted lease is an error requiring manual reconciliation, never absence permitting automatic cancellation. Native/Python caller features now require prepared_message_recovery_v1; upgrade the provider and Python entry together.

Expired sealed bytes are still recovered and journaled for evidence. They become UNKNOWN before any write; dispatch refuses an expired candidate, native recheck separately enforces its exact signed wallet expiry and fresh one-use permit, and existing proven terminal nonacceptance is required to retire an uncertain attempt. An RPC/lookup/validation error preserves reservations even after expiry. Only a successful native absent-lease result permits cancellation of an expired never-prepared job. Historical retired/sent bytes convey no new authority: existing live/sent/permit/evidence guards remain in force.

The daemon's default-disabled/testnet/pilot gates, custody, pending/budget limits and public protocol are unchanged. Recovery is an internal bounded tick operation, not an HTTP endpoint chosen by clients. No engine, consensus, contract, circuit or key format changes.

Regression and retained sensitivity evidence is in test/bonded-relayer/native_faults/PREPARED-RECOVERY-EVIDENCE.md. Historical native lookup proves exact existing bytes after quote expiry; it is distinct from a fresh chain execution after a deliberately lost prepare reply. The local acceptance matrix must complete that latter case before public pilot enablement.
