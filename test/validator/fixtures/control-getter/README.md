# Bounded control-getter core validation

## Inputs and execution

`elector-data.boc` is public account data from the saved development-network elector
state used by the design probes at `e7af7d3f8`. SHA-256:
`3150c331f4c317786a8f3308a535a4713abcfc9f20921a30047e0d1c27764d9a`.
It contains an open election, past election and credits. Tests grow each dictionary
and assert every result's shape, counts and values before recording gas.

Contract code is **not frozen here**: the test fixture includes the elector and
config C++ code generated by `gen_fif` from the current contract sources. Both native
test targets depend on that generator. A later contract change therefore reaches
the measurement, rather than silently exercising the saved BOC. New inputs live
under `test/`; these tests do not read `doc/evidence/`.

The account is loaded from a constructed masterchain snapshot through the core's
actual parser. Execution uses the shared production c7 and library construction,
full account balance, debt, global version, state time and logical time, config and
previous blocks. Signature checks stay enabled. No resulting c4/c5 is persisted or
executed. A test modifies c4 and confirms the next run starts from the original
account. A snapshot provenance check refuses mixing an account with another state's
context.

## Budget gate

The exact production measurements are in `budget-results.txt`. The elector gate
requires `(budget - gas) / gas >= 30%` for each measured shape and the combined read.
It uses integer comparisons, not rounded display values.

| Worst case | Gas | Ceiling | Headroom | Unused |
| --- | ---: | ---: | ---: | ---: |
| 256 deepest-path participants, maximum-width stake | 1,114,595 | 1,500,000 | 34.5780% | 25.6937% |
| 16 deep-path past elections, 4,096 frozen entries | 19,528 | 50,000 | 156.0426% | 60.9440% |
| Deepest returned-stake lookup | 26,804 | 40,000 | 49.2315% | 32.9900% |
| Combined read, 16 distinct wallets | 1,552,487 | 2,190,000 | 41.0640% | 29.1102% |

Contiguous and hashed history IDs cost 15,953 and 17,878 gas respectively. The
aggregate control lowers only the request budget: participant and history runs
succeed, the returned-stake VM also succeeds within its own budget, and the aggregate
charge refuses before its decoder runs. Per-getter exhaustion is separate coverage.

Proposal gas is an **operational ceiling**, with no headroom guarantee. The measured
whole-result envelope includes 4,096 hashed unvoted proposals (9,431,419 gas), 512
deep-path proposals with 21 voters (8,547,745), and a single lookup costing up to
38,512. Larger cases are explicitly refused before decoding. In the hashed unvoted
VM-only boundary control, 4,339 entries succeed at 9,999,336 gas and 4,340 fail at
10,000,024. These exceed the response count bound: they isolate the gas guard and
are not supported response sizes. A separate real-getter control returns 4,097
entries successfully from the VM and is refused by the 4,096 count guard. Reply-budget
controls reserve wrapper bytes first: exactly 8 MiB fits, one more byte refuses.
Actual TL wrapper sizing is integrated with the handlers in the next commit.

## Reproduce the gates

Use the worktree's own build, configured as in commit 1 with clang-21, Ninja,
Release, `TOS_WERROR_BUILD=ON`, the CI architecture flags and ccache. Do not set
`CCACHE_BASEDIR`.

```sh
cmake --build build --parallel 16
ctest --test-dir build --output-on-failure --no-tests=error \
  -R '^(control-getter-|getter-context-(context|vm|libraries|liteserver)$|test-vm$|test-proof-verify$|test-liteserver-admission$|lite-query-error-response-source$)'
CARGO_TARGET_DIR="$PWD/build/rust-target" RUSTC_WRAPPER=sccache \
  cargo test --manifest-path tosctl/src/Cargo.toml --workspace --no-run --locked --jobs 16
cargo fmt --manifest-path tosctl/src/Cargo.toml --all --check
python3 scripts/check-branch-chain-python-ci.py
uv tool run ruff check test/validator/control-getter-mutations.py \
  test/validator/getter-context-ci-controls.py scripts/check-branch-chain-python-ci.py
git clang-format-21 --binary clang-format-21 --diff d79447d71 -- \
  validator-engine/control-getter.cpp validator-engine/control-getter.h \
  validator-engine/control-getter-executor.cpp validator-engine/control-getter-executor.h \
  test/validator/control-getter-test.cpp test/validator/control-getter-budget-test.cpp \
  test/validator/control-getter-fixture.h test/validator/getter-context-fixture.h
git diff d79447d71 --check
```

All commands exit 0. Native CTests: 17/17. No Rust source changed, so touched-crate
clippy and crate-specific tests are not applicable. The native full-target build
includes the engine and both core test binaries and uses `-Werror`.

## Red/green controls

```sh
python3 test/validator/control-getter-mutations.py --build build --jobs 10
python3 test/validator/getter-context-ci-controls.py --build build
```

Each production control has its own detached worktree and Ninja target, using the
candidate's actual strict compiler flags and unchanged dependency archives. No
primary source is mutated. Baseline and restored runs must exit 0 and report checks;
the mutant must exit 1 with its named assertion. A compile/setup error, missing or
multiple anchor, timeout or zero checks is a failed control run.

Append `--only NAME` to reproduce one control. `controls.json` records exact source
file, line, suite, assertion, anchor count and green/red/restored exits. The runners'
`CONTROLS` and `CASES` maps specify the exact substitutions. Controls cover active
and queued caps, repeated dispatch, cancellation retention, shutdown, worker startup,
worker exceptions, aggregate and per-run gas, snapshot identity and provenance,
signature checks, context, libraries, c4 immutability, list arity/count/visitor
errors, reply bytes, the existing iterative reference deletion queue, the 30%
headroom gate and CI build/selector/registration coverage.

The small-stack deletion control creates and releases a 200,000-node tuple chain
on a 256 KiB thread stack in a subprocess. Replacing the deletion queue with recursive
delete makes the child fail and the parent emit the intended assertion.

This commit introduces the core and tests; control-query TL types, real engine
handlers and client routing remain subsequent commits. The heartbeat test uses a
stand-in control actor while a worker is held, not a live engine query. No validator
service was restarted, redeployed or queried.
