# Reproducible V5R2 review candidate

The [compact manifest](review-candidate-manifest.json) freezes 74 file identities
for an **unapproved review candidate**. It covers the ordinary wallet, module
and fee-vault code; actual ConfigParams; contract/compiler-adapter sources;
TL-B, opcode/error definitions; SDK codecs; and the public crypto/KDF/wire
vectors currently included by the builder. This is not a complete ACVP inventory
or an approved production release.

The frozen configuration uses the public test namespace `0x42` repeated 32
times, global ID 1, version 18, basechain credit 20,000 and masterchain credit
10,000. Its ConfigParams SHA-256 is
`3d480a6c3d9eed12b6ea687ab75f9d0a5fbcbbbad780a003af6c17a1ec6f72c7`.
The wallet code embeds this namespace; a deployment under another namespace
needs its own reviewed code/configuration identities.

These match the code exercised by the selected generated-config fee and PRIMARY
transaction corpora. The decoder rejects exotic/library cells at every depth;
the compiled module and wallet do not contain a classical signature opcode.
The module embeds the vault dependency, and the wallet embeds the vault and
pins the module hash. The ABI JSON preserves source constant expressions and
numeric throw operands; the canonical wire schemas/codecs are included verbatim.

## Rebuild and verify

Build the native tools from the reviewed source as in the rescue workflow.
Set `FUNC_PATH` and `FIFT_PATH` to those binaries. Use the actual ConfigParams
produced by `admission_config_controls.py`; run its source mutations exclusively.
Then use a new output directory:

```sh
python scripts/build-wallet-v5r2-bundle.py \
  --config GENERATED_CONFIG.boc \
  --expected-manifest test/wallet-v5r2/review-candidate-manifest.json \
  --output-dir NEW_BUNDLE
python scripts/build-wallet-v5r2-bundle.py \
  --config GENERATED_CONFIG.boc \
  --expected-manifest test/wallet-v5r2/review-candidate-manifest.json \
  --check NEW_BUNDLE
```

The builder copies all included source/vector files into the generated bundle.
The compact manifest in Git avoids storing those duplicate contents. Comparison
pins `config`, `code` and `files` against actual regenerated bytes. Both manifests
must retain the supported format and `unapproved-review-candidate` status.
Compiler binary hashes and Git metadata remain per-build provenance; different
architectures must reproduce the stable identities rather than identical native
compiler executables.

Changing a frozen source, schema, vector, included license or generated code
requires an explicit reviewed refresh. Build a new candidate without
`--expected-manifest`, inspect its changes, and update only the stable manifest
fields (`format`, `status`, `config`, `code`, `files`) after the relevant semantic
tests. CI never refreshes the pin automatically. Neither refreshing this test
candidate nor passing comparison authorizes production activation.

## Controls and retention

`release_bundle_controls.py` runs a normal build, reproduction and final check;
eight changed/missing/extra-file or identity refusals; and two actual CLI refusals
for bad expected namespace/status. Five in-memory guard deletions must make the
same negative assertions fail, including deletion of the CLI option's call site.
The bad-expected controls require native code to exist before a semantic refusal
counts. Compilation failures do not satisfy them.

[Local evidence](review-bundle-20261006.json) includes exact commands, code/config
identities, source hashes and short red assertions. The full generated bundle
and logs are retained in rescue CI artifacts for 14 days when that run executes;
local scratch paths have no guaranteed retention. The final-head cross-architecture
run, complete vectors and independent release review remain separate gates.

After all client source guards were restored, an additional build and independent
check using Clang 18-built Func/Fift reproduced the same 74 frozen identities as
the earlier GCC-built tools. This is local compiler-build reproducibility; the
18 control outcomes above and final-head architecture CI remain distinct.
