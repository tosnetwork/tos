# Generated-config fixture roots

The two existing generated-config consumers retain their detailed reports and
all authored checks. `release_config_transactions.py` adds ten root records;
`post_accept_transactions.py` adds all five, including two external refusals
with exit 0/-14 and no resulting transaction. Thirteen real transactions compare
Transaction, Account and ShardAccount roots. Accepted compute/action failures
retain roots. No storage metadata is recomputed to manufacture agreement.

`generated_roots.py` binds the original ordered population, fresh predecessor
hash/LT, actual fixed time and LT sequence, Account address/workchain/code/data,
message shape/body, seed, library/default previous-block context and signature
checking. Native accepted transaction headers, message reference, state update
and returned wrapper bind output to that input. Rejected rows have no native
header; their complete original context is checked against the fixed fixture
contract before admitting the exact refusal. They never synthesize resulting
Account roots. Replay uses independently seeded inputs, not continuous Rust
Account/cache carry.

The rescue workflow retains all 52 original serial step bodies and both
architecture gate names. New controls execute only in the two release-wallet
workers. The explicit bundle contains107 files: ten per generated family,
21 per Module execution lane (two modes, each fresh and recorded), both control
receipts and metadata. Limits are 2 MiB per file and 16 MiB total;
symlinks, unexpected paths/counts, missing files and digest changes fail. A
producer admits every input file and the complete metadata-inclusive size
before creating output paths or copying bytes. A
read-only GitHub metadata preflight bounds selection to 32 roots bundles, each
at most 16 MiB compressed, within 2048 run artifacts. It precedes the existing
official artifact downloader; reviewed producers bound their uncompressed files.
The five-minute final job budget remains.

Both original final gates still require every scheduled suite to succeed and
verify all suite-success receipts. They additionally check every candidate
roots bundle before selection. Source/event/run/attempt/suite/runner identities,
control coverage and actual native/root/legacy contents are verified. The chosen
bundle must match that architecture's newest successful release-wallet receipt
exactly. A retained earlier successful architecture attempt is valid when only
the other worker reruns; a malformed newer bundle fails rather than falling
back. The generated pair compares complete original inputs/raw config and root
outcomes, independently recomputed from native BOCs. Module fresh signatures
legitimately differ: each native/Rust raw root pair is checked, then deterministic
fixture effects and exact fixed-replay inputs/config/native/root outcomes are
compared across architectures. No output hash is normalized.
