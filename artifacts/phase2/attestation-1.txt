## What happened

A scalar was drawn from /dev/urandom inside phase2-contribute, applied, and
wiped. It was never a return value, never written to a file, and cannot be
printed -- the type that holds it has no Display and its Debug prints a
placeholder, so logging it does not compile. Nothing on this machine holds it.

The starting key was rebuilt from the committed phase-1 slice before
contributing and matched the announced digest, so this contribution was
applied to the key this repository's slice and circuit determine, not to
whatever was in the directory.

## What this contribution is worth, stated plainly

**It was made by an automated agent operating the machine of the party
deploying this pool, and it adds nothing to the trust set beyond that party.**

The security argument is that at least one participant destroyed a scalar
without the others being able to compel or observe them. This does not satisfy
that for anybody except the operator: the agent genuinely cannot see the
scalar, but the trust boundary is the machine, not the agent, and the machine
is the operator's. Counting this as an independent contribution would be
counting the operator twice.

**So this ceremony currently rests on nobody.** It starts being worth
something at contribution 2, if contribution 2 comes from someone who can fail
independently of the operator.

## Unsigned, and why

A signature is worth what the identity behind it is worth. An agent has no
identity that predates this ceremony, and generating a key to sign with would
produce a signature anyone could have made -- worth exactly what no signature
is worth, while looking like more.

If the operator wishes to stand behind this contribution, the right signature
is theirs, made with a key that was already publicly theirs:

    gpg --local-user <key-id> --clearsign \
        --output artifacts/phase2/attestation-1.txt.asc \
        artifacts/phase2/attestation-1.txt

That would say something true: the party who controls the machine vouches for
what ran on it. Nothing else here can.
