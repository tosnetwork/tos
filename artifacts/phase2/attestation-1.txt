## What happened

A scalar was drawn from /dev/urandom inside phase2-contribute, applied, and
wiped. It was never a return value, never written to a file, and cannot be
printed -- the type that holds it has no Display and its Debug prints a
placeholder, so logging it does not compile. Nothing on the machine holds it.

## What this contribution is worth, stated plainly

**It was made by an automated agent operating the machine of the party
deploying this pool, and it adds nothing to the trust set beyond that party.**

The security argument is that at least one participant destroyed a scalar
without the others being able to compel or observe them. This contribution
does not satisfy that for anybody except the operator: the agent genuinely
cannot see the scalar, but the trust boundary is the machine, not the agent,
and the machine is the operator's. Counting this as an independent
contribution would be counting the operator twice.

It is here because a chain has to start somewhere, and because contributions
2..N are where the property comes from.

## Unsigned, and why

A signature is worth what the identity behind it is worth. An agent has no
identity that predates this ceremony, and generating a key to sign with would
produce a signature anyone could have made -- worth exactly as much as no
signature, while looking like more.

If the operator wishes to stand behind this contribution, the right signature
is theirs, made with a key that was already publicly theirs:

    gpg --local-user <key-id> --clearsign --output attestation-1.txt.asc attestation-1.txt

That would say something true: the party who controls the machine vouches for
what ran on it. Nothing else here can say that.

## Known gap in the announcement

**The beacon had not been named when this contribution was made.**

doc/shielded-pool-phase2-runbook.md requires the beacon -- its source, its
exact height or round, and its witness -- to be published before the ceremony
opens, because its entire property is about *when* it was chosen and no
program can check that afterwards.

It was not, and this record says so rather than leaving it to be noticed. The
gap is recoverable: nothing is deployed, no address is published, and redoing
the ceremony costs only the time. **It must be closed before contribution 2**,
or every later contributor inherits a ceremony whose anchor could have been
chosen to suit the contributions already in it.
