# Observation review disposition

The first read-only review found real instrument and provenance gaps. Its
working transcript remains outside the repository in the review directory.
The initial archive changed during that review; final-source runs below
supersede those checkpoints, which remain retained as history.

- Breakpoint binding: the final observer records location, pending, enabled and
  validity before execution. The classifier requires all eight bound sites.
  The same Watch implementation demonstrably counts registry/variant/refusal.
  We do not open the gate to exercise its unreachable downstream visitors.
  The collator visitor's zero is structural on direct validator import, not
  independent evidence about collation; validator visitor zeros concern this run.
- Execution-count calibration: the existing native engine-body selftest records
  `config=0, execute=1`. The initial command omitted its required path argument;
  that CLI error is retained and is not a control pass.
- Export/accept calibration: a real singleton import delivers CandidateAccept and
  creates the export file. A separate observation control supplies an export
  file and must fail. This is not AccountBinding execution acceptance.
- Stale acknowledgement: validation now writes pending before dispatch. Removing
  the final recorded write leaves pending and fails directly. Acknowledgement
  proves callback receipt and field writes, not reachability: the validator
  stack and registry-site observations supply reachability separately.
- Counts are correlated sites on one control flow, not three independent
  predicates. Entry, typed variant selection and refusal expression are reported
  separately to locate the stop. Exact messages and shapes jointly classify it.
- Missing controls: final observation controls also cover nonzero counts, wrong
  types/status/content, observer errors, wrong host, unbound observation, actual
  execution and export. Native CandidateReject is checked by the rerunnable
  separation driver, not merely a saved traceback.
- The invalid-file-hash rejection calibrates the terminal variant writer before
  registry; it does not prove a CandidateInvalid branch at registry. That gate's
  capability failure must remain local. No such rejection claim is made.
- Provenance: report names both committed merge inputs; base-tree manifest and
  disk-observer patch are retained. The transient tree is reconstructible from
  those inputs and is not presented as a fetchable integration commit. Actual
  fixture identity inputs and final checker sources are included and hashed.
  Failed relink files are explicitly abandoned preparation evidence, not the
  final build method. Probe resolves symbols and refusal line afresh per binary;
  archived line numbers are not replayed against another source.
- The earlier failure is deliberately supplied by the existing configuration
  fault option, observed through the native validator, not an organic incident.
- Disk-tool write failure remains fail-closed, matching surrounding ensure-style
  handling; it is not relabelled as a consensus failure. Unique run directories
  prevent old trace reuse. This is a run precondition, not a GDB guarantee.
- Real classification checks use explicit failures, so optimized Python cannot
  erase their acceptance checks. Python bytecode caches are ignored and excluded
  from the explicit commit list.

No review finding authorizes moving the readiness refusal or changing its
classification. Measurement remains controlled `is_fake` disk import, never a
claim of production-network reachability.
