# T12: retire the installed classical Validator.fif library

The pre-T12 `crypto/fift/lib/Validator.fif` (SHA-256 `70b13a78ca93e2f062ffe1b4352efef8fa7c88c92615768ee01caf387e26de3b`) defined only the classical Ed25519 signature parser/check, `0x654c5074` election preimage and `0x4e73744b` stake-body words. It held no still-needed non-stake implementation: its `Addr.fif`, `Currency.fif`, `Key.fif` and `Msg.fif` includes were transitive conveniences, and those generic libraries remain installed. The actual remaining include consumers were **five test inputs**: four `crypto/test/fift/fixtures/*legacy*elect*.fif` historical byte fixtures and `crypto/test/fift/validator-proposal-invalid-signature.fif`. A sixth dependency was `crypto/fift/utils.cpp` unconditionally preloading `/Validator.fif` into every memory Fift run. No product script includes it after T10/T11. `Validator.fif` was also present in the T11 fresh install and full local ZIP.

T12 moves the executable words into `crypto/test/fift/fixtures/ValidatorLegacy.fif` (SHA-256 `2cd98dea9bdbec9d501b41e5a34055a17f44f897ca9b99eeca093b5a5023e0d7`). After stripping comments and trailing whitespace, `diff -u` against the pre-T12 product file exits 0: the historical codec operations are unchanged. All five test inputs now include that test-only filename. `test-smartcont.cpp` injects it into exactly the four historical fixture lookups; `test/fift.cpp` injects it only for the invalid-signature negative. The latter now requires the exact 64-byte-length error, so a missing include cannot pass as an arbitrary expected failure. `crypto/fift/utils.cpp` no longer preloads the product library. The product file itself is deleted; the generic Fift libraries remain.

The source guards check both halves: product `Validator.fif` and its memory-loader preload must be absent; no scanned product `.py/.fif/.fc/.cpp/.rs` file may name a classical `validator-elect-body` word; and the exact test-only include/injection inventory must remain. `check-removed-validator-authority.sh` previously treated a missing product library as an instrument failure because it scanned five vote/admin tags inside it. T12 replaces those five now-inapplicable scans with a direct refusal if the entire retired product file returns. The new test-only codec is not installed. The inventory changes from six T11 source files to eight test-side source files at T12 because the codec, the fifth input and its C++ harness are now counted explicitly. It is **not** eight product stake paths.

All original logs and reversible mutation patches are retained under `test/integration/.t12-validator-library-retirement-20260924/`, outside Git:
