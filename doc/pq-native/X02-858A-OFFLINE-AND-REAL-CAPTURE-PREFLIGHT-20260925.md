Two production-shape issues were found before fault injection:

1. `ValidatorElectionRehearsal.readiness_manifest()` emits `tos.validator-election-experiment-readiness.v2` with `schema_version=2` and `mode=experiment`; the c66 X02 checker required v1. Changing the synthetic positive fixture to v2 made the old checker fail exactly at `Stage A readiness provenance differs` (raw `schema-v2-old-red.typescript`, SHA-256 `6a23cddd46784957d72a65ab2df239d5c6afad6dea581f1250a35d8b222d8ade`, exit 1). Local commit `34bf8bf06` now requires the actual v2 shape and rejects stale v1; the full suite passed 86/86 (raw `schema-v2-new-green.typescript`, SHA-256 `23cc4ce60b9eccced130092774e34ae6a7631511232dbd4d21432dda1828f29a`, exit 0).
2. The X02 recorder/checker calls `journalctl -u validator-1 ...` and requires native marker entries with the validator's trusted journald `_PID`, cursor and monotonic timestamp. Stage A launches validators as direct `tostester` subprocesses and streams stderr to `network/nodeN/log`, not a `validator-N` systemd unit. On this host `journalctl -u validator-1 --no-pager -n 3 -o json` exited 0 with no entries (`journalctl-validator-1.typescript`, SHA-256 `3b1e81edfd8844067db12e1261910d5b80904e160c0d257734bbf8ebdfe321d3`). By contrast the retained X01 node1 native log has 477 `BlockFinalizedInMasterchain` lines, file SHA-256 `00baccfce63374804ef4c7a8f470d25d83c15edf30254097bf29214166e5b0f1`. A forwarder would have its own `_PID`, so it cannot be silently substituted for validator-origin journald entries.

The second issue is a capture-provenance blocker, not a consensus or tc result. Next code cut must either launch actual validator processes as journal-backed units while preserving the harness PID/DB identity, or capture incremental native node-log bytes with exact file/PID/inode and event-time/cursor continuity controls. Then a new fixed-tree red/green control and separate four-node directed tc run must measure per-direction hit/drop, per-height full ID/native/header joins and 120/60/180-second windows. No 100% isolation or partial-loss claim is made here.
